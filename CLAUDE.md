# Occupy Mars — working notes for Claude

- Vite 8 + React 19 + TS; three.js via @react-three/fiber + drei; zustand; vitest. `npm run build` runs `tsc -b` first — keep it type-clean.
- Physics lives in `src/sim/` and is pure TypeScript (no DOM) so it runs in the worker (`src/sim/worker.ts`) and in Node scripts/tests. Every number in `src/data/vehicles.ts` and `src/sim/*` should trace to `docs/research/` with a confidence tag (Y/O/D/T). Unpublished numbers become config sliders, not constants.
- Validation: `npm test` (anchor tests against NASA windows, USSA76, orbit propagation + mission-level expectations). `npx tsx scripts/mission-check.ts [vehicle] [preset] [window]` prints a full timeline; `scripts/ascent-check.ts`, `scripts/entry-calibration.ts` for the parts.
- Visual checks: build, then `node scripts/shot.mjs out.png W H waitMs "?vehicle=<id>&preset=<id>&window=<id>&t=<missionSeconds>" ["<click selector>"]` (headless Chromium with software WebGL, pre-installed at /opt/pw-browsers; CSS transitions do not advance there, the script disables them when clicking). `?model=<id>&view=side|nose|engines|mid&az=<deg>` shows a vehicle alone; `?terrain=mars|cape&pad=<padId>&alt=&az=&pitch=&x=&z=` the ground alone. Under SwiftShader the page is 10× slower than real hardware — don't tune timings to it.
- Places: `src/scene/capeSite.ts` (geography, canvas maps, pad ids/decks) + `pads.tsx` (procedural pad structures; the NASA Mobile Launcher GLB is Draco-compressed, decoder in `public/draco`) + `CapeCanaveral.tsx`; `src/scene/marsSite.ts` (DOM-free heightfields and per-pixel colour, shared with `marsMaps.worker.ts`) + `MarsSurface.tsx`. Terrain tiles are spherical caps (`terrain.ts: capGeometry`) built about the local origin; finer tiers match the coarser mesh at the seam and the coarser dips under them. Heightmaps are RG-encoded 16-bit PNGs from NASA-3D-Resources STLs (`scripts/stl2height.py` to regenerate).
- Orbit: `src/scene/Earth.tsx` (scene unit = 1 km; day/roughness/cloud/star maps in `public/assets/earth`, built by `scripts/earth-assets.py` from NASA-3D-Resources). The limb halo is a BackSide sphere that must stay *below* the orbit radius (EARTH_R + ALT) or it fills the sky.
- UI: the stage is the whole screen. `TopBar` (picker, Mission/Data toggles), `VerdictCard` (≤4 stats), `Stage` (scene + live numbers + mission bar + playback loop), `MissionDrawer`, `DetailsSheet`. Tracked uppercase `.label`s, glass panels, three text opacities — keep new UI in that register.
- 3D models are procedural in `src/scene/vehicles/*.tsx`; stage groups are named by the sim's stage ids and carry `plume:<stageId>` anchors; `VehicleRig` animates them. `SPACECRAFT_GROUP/BASE/LENGTH` in `src/scene/vehicles/index.tsx` must match the model geometry.
- Mission time (s) is the playback axis; phases carry their own playback rates (`PHASE_RATE` in the store).
- Site language is English; the research report is Turkish, the notes English. Don't link the repo from the site (owner's request).
- Commits: small and frequent, pushed to `main` (Vercel deploys from it).
